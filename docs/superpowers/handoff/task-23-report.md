## What I implemented

- `.github/workflows/publish-extension.yml` — mirrors GitTools' `publish-extension.yml`:
  - Triggers: `push` to `main` with the path filter `src/**`, `scripts/**`, `package.json`, `package-lock.json`, `esbuild.mjs`, `tsconfig.json`, `.vscodeignore`, `README.md`, `CHANGELOG.md`, `docs/images/**`, `media/**`; `push` of tags `v*`; `workflow_dispatch` with optional `version` input.
  - `permissions: contents: read` at the top; job `publish` has `contents: write`. `concurrency: { group: publish-extension, cancel-in-progress: false }`.
  - Steps in order: checkout (`fetch-depth: 0`); setup-node 22 + npm cache; `npm ci`; `npm run lint`; `npm run build`; `npm run check:size`; `npm test`; "Define the extension version" (id `version`: manual input → tag without `v` → `node scripts/extension-version.mjs`; validated `x.y.z` in Node; written into the root `package.json`; output `version`); "Release notes (from the CHANGELOG)" (`node scripts/release-notes.mjs "$VERSION" "$RUNNER_TEMP/release-notes.md" "$MODE"`, `neutral` only when `event_name == push && ref_type == branch`); `npm run package` with `NODE_ENV=production`; Marketplace (id `marketplace`, `npx vsce publish --no-yarn --packagePath release/coverage-tools-"$VERSION".vsix`, outputs `published` and `configured`; "already exists" → notice; no secret → warning, `published=false`, `configured=false`); Open VSX (`npx ovsx publish release/coverage-tools-"$VERSION".vsix -p "$OVSX_PAT"`; already published → notice; no secret → skipped); `softprops/action-gh-release@v2` with `if: github.ref_type == 'tag' || steps.marketplace.outputs.published == 'true' || steps.marketplace.outputs.configured == 'false'`, `tag_name` = tag or `v<version>`, `target_commitish: ${{ github.sha }}`, `files: release/*.vsix`, `generate_release_notes: false`, `body_path: ${{ runner.temp }}/release-notes.md`; `actions/upload-artifact@v4` named `coverage-tools-vsix`.
  - Every event value (`github.event.inputs.version`, `github.ref_type`, `github.ref_name`, secrets, ALLOW_NEUTRAL) reaches the shell only via `env:`. Comments are in English.
- `scripts/extension-version.mjs` — `nextExtensionVersion(fileVersion, tags = [])` (same rule as GitTools); `main()` reads the ROOT `package.json` and `git tag -l 'v*'`, runs only when executed directly.
- `scripts/release-notes.mjs` — `releaseNotes(changelog, version, allowNeutral)` returns the trimmed `## [<version>]` section (up to the next `## `); otherwise the `### Done` list under `## [Unreleased]` (up to the next `###`/`##`); with nothing to say (no bullet, or only "Nothing yet.") returns `Maintenance release.` when `allowNeutral`, else throws. An existing but empty version section always throws (as in GitTools). Invalid version throws. CLI: `node scripts/release-notes.mjs <version> <output> <neutral|strict>` reads the root `CHANGELOG.md` and writes the body + newline.
- `scripts/extension-version.d.mts`, `scripts/release-notes.d.mts` — type declarations so the TS tests import the `.mjs` files without loosening tsconfig (verified with `tsc --traceResolution`: `'../../../scripts/release-notes.mjs' was successfully resolved to '.../scripts/release-notes.d.mts'`).
- `CONTRIBUTING.md` (English) — Development commands + "Publishing": local `.vsix` build, when the workflow runs, how the version is chosen, release notes, one-time setup of `VSCE_PAT` (Azure DevOps PAT, scope Marketplace → Manage, publisher `DaniloFG`, same as GitTools) and optional `OVSX_PAT`, and what happens without the secret.
- `media/icon.png` — 128×128 RGBA PNG, teal rounded square with a white check mark and a bar underneath (1125 bytes). Generated by a Python stdlib (`zlib`/`struct`) script kept out of the repo (scratchpad `make_icon.py`). Not referenced from `package.json`.

## Deviations / concerns
- **CI concern:** `npm test` in CI (both `ci.yml` and the publish workflow) now runs `publishWorkflow.test.ts`, which needs `python3` with PyYAML on the runner. I believe `ubuntu-latest` ships PyYAML, but I could not verify it here; if it does not, add `pip install pyyaml` (or `actions/setup-python` + pip) before `npm test`, or the packaging task can verify on the first CI run.
- Version step: GitTools wraps validation/writing in `if [ -n "$VERSION" ]`; I dropped that wrapper so an empty version fails validation instead of silently keeping the file version (an empty result cannot occur otherwise). The tag name comes from `env: REF_NAME: ${{ github.ref_name }}` instead of the runner's `GITHUB_REF_NAME`, as the dispatch asked for `github.ref_name` through `env:`.
- The vsce command uses `--no-yarn` (as instructed) instead of GitTools' `--no-dependencies`, because `c8` is a runtime dependency that must be packaged.
- `CONTRIBUTING.md` has a short "Development" section (command list) before "Publishing".
